# Glosario

| Término | Definición |
|---|---|
| Agente | Rol configurado con una misión, límites, herramientas y contrato de entrada/salida. |
| Arnés | Entorno que ejecuta la arquitectura, por ejemplo Codex, Claude Code o Antigravity. |
| Auditor | Rol que evalúa si una decisión de aprobar, bloquear o escalar está justificada por evidencia y reglas. |
| Caso | Trabajo persistente identificado, como una campaña o encargo técnico. |
| Criterio técnico | Regla o condición explícita utilizada para evaluar un resultado. |
| Definition of Done | Conjunto verificable de condiciones para cerrar un work item o emitir un entregable. |
| Dominio | Tipo de trabajo con vocabulario, evidencia y método propios, como P.A.T. o COMTRADE. |
| Entregable | Artefacto preparado para el usuario: informe, matriz, galería, análisis o código. |
| Escalamiento | Transferencia de una decisión al responsable humano por falta de evidencia, ambigüedad o desacuerdo. |
| Evidencia actual | Información de la revisión vigente que sustenta hechos del caso. |
| Evidencia de finalización | Registro de que se cumplió la Definition of Done: QA, aprobaciones y validaciones. |
| Expediente | Paquete de solicitud, contexto, evidencia, restricciones y referencias de una revisión. |
| Full rework | Rehacer lo dependiente de una premisa base invalidada, preservando trazabilidad y componentes válidos. |
| Handoff | Entrega estructurada de artefactos y límites de un rol al siguiente. |
| Histórico aprobado | Entregable final validado que puede orientar forma y contexto, sin sustituir evidencia actual. |
| Integrador | Rol que ensambla componentes aprobados en un entregable coherente. |
| Manifest de entradas | Inventario de archivos, datos y fuentes de una revisión, con rol y estado. |
| NO EMITIR / no_emit | Estado que prohíbe distribución externa por un bloqueo crítico pendiente. |
| Orquestador | Rol que crea el work item, selecciona workflow, coordina etapas y valida intención. |
| Patch | Corrección local y aislada. |
| Partial rework | Rehacer una sección y sus dependencias directas. |
| QA visual | Revisión del documento renderizado para validar orientación, orden, legibilidad y correspondencia de evidencias. |
| Ready | Estado en que el expediente es suficiente para ejecutar una fase declarada, no necesariamente para emitir. |
| Ready for emission | Estado en que evidencia, revisiones y aprobaciones permiten emisión externa. |
| Revisión | Fotografía inmutable del expediente en un momento; una modificación crea una revisión sucesora. |
| Revisor técnico | Rol independiente que valida exactitud, trazabilidad, límites y criterios técnicos. |
| Skill | Procedimiento reutilizable que describe cómo realizar un tipo de trabajo. |
| Work item | Orden de trabajo interna creada por el orquestador a partir de un expediente y revisión. |
| Workflow | Secuencia declarada de etapas, roles, artefactos, compuertas y reglas de corrección. |
